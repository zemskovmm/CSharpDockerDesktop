# ENG-0002.rule-layer-separation

## Rule

Separate Presentation, Application, Domain, and Docker Infrastructure responsibilities. Presentation reaches Docker behavior through application services; Docker protocol and transport implementation remain independent of Uno.

## Applicability

Conditional

## Applies when

- Creating or changing module boundaries, application services, domain models, presentation integration, or Docker/platform infrastructure.

## Rationale

The source's MVP technology decision table selects these architecture layers. Its integration model keeps protocol behavior independent of presentation so it can be verified without the desktop UI and extended to another platform without redefining resource interactions.

## Guidance

Presentation owns views/navigation/commands and display behavior. Application owns operation/session coordination. Domain owns resource/state/error/capability concepts. Docker Infrastructure owns Engine requests, decoding, and transport integration.

Keep platform connection details below the presentation boundary. The source's example solution directories and private type names do not establish required file names or a fixed project count.

## Verification

Dependency and responsibility evidence demonstrates the selected separation. Engine protocol/transport behavior can be exercised without Uno views or a desktop UI session.
