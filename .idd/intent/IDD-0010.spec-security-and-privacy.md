# IDD-0010.spec-security-and-privacy

## Intent

Treat Docker access as privileged capability and protect the developer's data, host, credentials, terminal input, and container content.

## Related Specifications

IDD-0002, IDD-0003, IDD-0004, IDD-0005, IDD-0007, IDD-0008.

## Behavior

- Normal operation does not require Administrator elevation. Permission failures produce diagnostics rather than relaunching elevated.
- Never silently expose the daemon over TCP or offer insecure TCP exposure as a connection-wizard shortcut.
- If an insecure TCP endpoint is supported/encountered, warn that it lacks TLS; the source does not establish that warning as permission to add the transport to MVP.
- Inspection/browsing does not perform hidden resource mutations. Destructive actions follow the explicit confirmation and resource-specific safety contracts.
- Copy/export of sensitive data is deliberate and user-controlled. Raw Inspect remains actual Docker JSON.
- Do not record registry authentication, TLS private keys, terminal input, or container environment in application logging. Log contents are excluded from application logging by default.
- Do not transmit container/image names, labels, environment values, bind paths, raw Inspect, logs, terminal commands, or registry credentials through telemetry/crash reporting.
- Do not silently upload full-memory crash dumps that may contain this data.
- The MVP provides neither a plugin system nor a localhost management API, and does not execute arbitrary Docker requests from URLs/deep links.

## Product-Significant Architecture And Constraints

Daemon access can affect host resources even when the GUI process is not elevated. Connection diagnostics and error preservation must not weaken the no-credential/no-container-content logging requirements.

### Unresolved telemetry policy

Telemetry/crash reporting inclusion is explicitly unspecified in the source. Disabled-unless-opted-in is a recommendation, not an accepted imported product policy. No telemetry service, allowable event schema, or enabled default is created by this import. Any later decision remains subject to the prohibitions above.

Installer/signing/update-channel recommendations likewise remain unconfirmed delivery decisions, separate from normal-operation security.

## Non-goals

- Automatically changing Engine permissions or security configuration.
- Privileged exec controls.
- Extensions or unauthenticated local/deep-link control of Docker operations.
- Automatic transmission of sensitive diagnostics.

## Acceptance Criteria

- Ordinary use succeeds without elevation when the user already has Engine access.
- Access denial leaves a clear diagnostic and does not change host permissions or relaunch elevated.
- Volume/container deletion requires deliberate confirmation.
- Credentials, environment, and terminal input are absent from application logging. Log content is absent from default application logging, and all prohibited container content/metadata is absent from telemetry/crash payloads.
- Inspect/copy behavior preserves actual data while avoiding automatic external transmission.

## Verification

Evidence includes non-elevated use, denied-access recovery, destructive-action cancellation, unsafe endpoint setup, and representative sensitive values across logs, Inspect, environment, credentials, and terminal input. Inspect the resulting application diagnostics and any enabled reporting path for prohibited data.
