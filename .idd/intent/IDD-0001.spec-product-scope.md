# IDD-0001.spec-product-scope

## Intent

CSharpDockerDesktop is a lightweight desktop client for an existing local Docker Engine. It serves a developer's daily workflow: find resources, inspect their state, diagnose containers, read logs, execute an interactive command, view resource usage, and perform explicit lifecycle actions.

## Related Specifications

IDD-0002, IDD-0003, IDD-0004, IDD-0005, IDD-0006, IDD-0007, IDD-0008, IDD-0009, IDD-0010, IDD-0011.

## Behavior

- The initial delivery targets Windows desktop, with Windows x64 as the MVP delivery baseline.
- The user can navigate Containers, Images, Volumes, and Networks and open resource details.
- Container details expose Overview, Logs, Terminal, Stats, and Inspect capabilities.
- The connection and Engine state remain visible. An unavailable Engine leaves the application shell usable and provides recovery information.
- The client manages resources already exposed by the selected Engine. External CLI operations become visible without restarting the client.
- Persisted application data is limited to settings and preferences; Docker resource state is refreshed from the Engine.

## Product-Significant Architecture And Constraints

The Engine is the authority for Docker resources. The GUI is a client of that authority, not a replacement runtime or an independently authoritative resource database.

Windows named-pipe access is the initial connection contract. Future macOS or Unix-socket delivery does not imply current platform support. IDD-0002 owns transport compatibility, and IDD-0011 owns the lightweight operation requirements.

## Non-goals

- Installing, configuring, starting, or stopping Docker, a VM, WSL, or another container runtime.
- Compose project management or organizing the MVP UI around Compose projects.
- Kubernetes, extensions, or a plugin system.
- Container or volume filesystem browsing, file editing, or content search.
- Aggregated multi-container logs.
- Initial macOS delivery, SSH contexts, or an automatic standalone WSL socket bridge.

Image pull/push, registry credentials, telemetry, and additional TCP/TLS scope are unresolved decisions owned by IDD-0005, IDD-0010, and IDD-0002. Their feasibility in Docker does not make them required MVP features.

## Acceptance Criteria

- With an existing reachable Engine, the developer can complete the stated resource, logs, terminal, metrics, and lifecycle workflow.
- With the Engine stopped, the application opens and explains the connection problem without becoming unresponsive.
- No excluded runtime, Compose, or filesystem management is needed to complete the MVP workflow.

## Verification

End-to-end evidence covers a local Engine that is initially unavailable, subsequent connection recovery, resource discovery, container diagnosis, interactive exec, lifecycle operations, and external changes. Acceptance does not depend on the client installing or starting the Engine.
