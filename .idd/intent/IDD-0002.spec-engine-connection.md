# IDD-0002.spec-engine-connection

## Intent

Connect to a selected Docker-compatible Engine, establish a supported API contract, and make connectivity, compatibility, and daemon failures understandable.

## Related Specifications

IDD-0001, IDD-0006, IDD-0010, IDD-0012, IDD-0014.

## Behavior

- Resolve a Windows-accessible endpoint and obtain readiness, version, and Engine information.
- Support the local Windows Docker named pipe, including Docker Desktop with a WSL2 backend. A Docker-compatible alternative exposing a named pipe requires compatibility evidence.
- Display connection state, selected context, actual endpoint, transport kind, Engine version, daemon API maximum/minimum, negotiated API version, OS, architecture, and available capabilities.
- Distinguish a missing endpoint, denied access, incompatible API, a daemon error, and a transient connection loss.
- Recover after an Engine restart without requiring a GUI restart. Recovery restores authoritative state as defined in IDD-0006.
- Discovery can use installed Docker CLI context information; absence of the CLI must not prevent the named-pipe connection baseline.
- A Windows process must not present a WSL-only Unix socket path as a working direct Windows connection. Explain the unsupported endpoint rather than automatically exposing the daemon over insecure TCP.

## Product-Significant Architecture And Constraints

Connection setup uses the Docker readiness, version, and information contracts. Resource requests use the negotiated version rather than a hardcoded daemon version.

The source's explicit MVP compatibility baseline is client API 1.40. The client maximum is its tested schema maximum, not a permanently fixed version copied from research. A connection requires a compatible overlap with the daemon's supported range; otherwise report Unsupported. Unknown additive response fields must not break otherwise supported responses.

Resource disappearance, state/dependency conflict, invalid/incompatible requests, and daemon failures must remain distinguishable. Preserve the daemon's original message where it is available. Cancellation is normal termination; a lost mutation response is handled through reconciliation, not a blind retry.

### Unresolved connection scope

The source describes a user-configured secure TCP/TLS endpoint as supported transport-wise, while also labeling TCP/TLS optional and remote TLS connection UI post-MVP. This import does not select either scope. Required MVP transport is the local Windows named pipe; TCP/TLS inclusion and setup UX remain a product decision. Security requirements apply to any TCP endpoint that is subsequently supported.

### Unconfirmed discovery precedence

The source proposes explicit application selection, then environment configuration, then the active Docker CLI context, then the Windows default pipe. It does not resolve precedence between DOCKER_CONTEXT and DOCKER_HOST. Exact environment precedence and the complete proposed discovery ordering need confirmation before they become a fixed compatibility contract.

## Non-goals

- Starting or repairing the Engine, elevating the GUI, or changing daemon network exposure.
- Implementing SSH contexts or a WSL socket bridge in the initial MVP.
- Treating an example research API maximum as a guaranteed supported version.

## Acceptance Criteria

- A reachable named-pipe Engine produces usable Connected information with its negotiated API.
- An incompatible daemon is reported as Unsupported before incompatible resource operations are attempted.
- Missing-pipe and access-denied cases produce distinct recovery diagnostics.
- Starting the Engine after the GUI is open restores connection and data without restarting the GUI.
- A WSL-only socket and unsupported context scheme produce a useful explanation.

## Verification

Evidence covers older and newer daemon API ranges, incompatible ranges, additive JSON fields, named-pipe readiness and permissions, CLI absence, endpoint selection, and Engine restart. Transport availability is verified on real Windows configurations, not inferred solely from a discovered context string.
