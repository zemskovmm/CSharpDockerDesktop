# IDD-0007.spec-container-logs

## Intent

Read recent container logs and follow live output with useful search and stream filtering while keeping memory and UI work bounded.

## Related Specifications

IDD-0003, IDD-0004, IDD-0006, IDD-0010, IDD-0011.

## Behavior

- Open a limited historical tail and allow live follow. Do not load all history by default.
- Provide plain-text search and stdout/stderr filtering when those streams are distinguishable.
- Preserve available timestamps and offer pause/autoscroll controls for reading a live view.
- Clear removes only the local view buffer; it must not alter Docker logs.
- Handle transient disconnection with reconnection. Resume near the last observed timestamp with a small overlap and deduplicate that reconnect window instead of downloading complete history.
- Bound retained text/entries and evict old entries when the configured bounds are reached.
- Present an understandable unavailable state when the configured logging driver cannot provide logs.
- Close/cancel the session and release resources when its view ends or its container disappears.

## Product-Significant Architecture And Constraints

For non-TTY output, interpret Docker's stdout/stderr multiplexing; for TTY output, preserve combined output rather than inventing separate streams. Arbitrary read, frame, character, and line boundaries must not corrupt UTF-8 or the displayed content. Partial frames, very long lines, malformed input, and EOF must not cause unbounded allocation or an unresponsive view.

Search and output delivery remain responsive under producer load. Regex search is optional; if added, it must be cancelable/debounced.

### Unconfirmed tuning and pause semantics

The source recommends a 500-line initial tail, 100,000 retained entries, a 32 MiB text budget, 100–250 ms UI batches, jittered backoff up to about ten seconds, and a one-to-two-second reconnect overlap. These are profiling candidates, not imported fixed limits. Bounded storage, limited initial history, recovery, and responsive delivery are required.

The exact behavior of Pause on ingestion versus presentation is not established by the source. It must be decided without removing the bounded-memory and responsive-reading guarantees.

## Non-goals

- Aggregated multi-container logs in the initial MVP.
- Clearing or deleting daemon log storage.
- Regex support as a mandatory feature.
- Unlimited history or unbounded per-tab retention.

## Acceptance Criteria

- Recent output appears and new output follows without blocking UI interaction.
- Stream filtering and search work with distinguishable stdout/stderr output.
- TTY logs display correctly as combined output.
- A transient disconnect recovers without replaying all history; overlap handling does not become a global identical-text filter.
- Sustained logs faster than rendering keep memory bounded.
- Unsupported-driver and deleted-container cases terminate with useful states.

## Verification

Evidence covers randomly fragmented multiplex headers/payloads, split UTF-8 sequences, line endings, very long lines, partial EOF, bounded eviction, high-volume output, reconnect overlap, unsupported logging drivers, and external deletion with Logs open. No secret log content is included in diagnostics or telemetry evidence.
