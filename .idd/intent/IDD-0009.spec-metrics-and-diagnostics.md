# IDD-0009.spec-metrics-and-diagnostics

## Intent

Explain a container's condition and resource consumption with accurate live metrics, bounded history, and direct daemon diagnostics.

## Related Specifications

IDD-0003, IDD-0004, IDD-0006, IDD-0010, IDD-0011.

## Behavior

- Stats shows CPU percentage, memory usage/percentage, network received/sent activity, and Block I/O read/write activity with charts.
- Label Block I/O as I/O activity rather than container disk-space usage.
- Obtain continuous stats only for the actively viewed selected container; the general Containers table does not open one continuous stream per row.
- Close the stats stream when the view is no longer active.
- Display samples at approximately one Hz and retain a default five-minute history in memory.
- Do not present stopped-container live stats as valid current measurements.
- Diagnostics exposes available health state, exit code, OOMKilled state, restart count, container state errors, and daemon error messages.
- Distinguish unavailable fields from valid zero values and refresh diagnostic state through inspection/reconciliation.

## Product-Significant Architecture And Constraints

Metrics are derived from Docker counters. CPU percentage uses changes in container CPU and system CPU with the applicable CPU count. Network and Block I/O rates use counter deltas over elapsed time. Handle zero denominators, counter resets, missing fields, and cgroup differences without invalid or misleading values.

Memory presentation follows the cache-adjusted semantics of Docker CLI stats rather than simply presenting raw usage as the same metric. Raw metric availability can vary by daemon/container platform.

History is bounded and memory-only. The source's additional history durations, wider dashboards, and optional one-shot sampling strategies are future candidates, not required MVP scope.

## Non-goals

- Continuous per-container stats across the entire resource table.
- Durable metrics storage or indefinitely growing chart history.
- Calling Block I/O counters a measurement of filesystem disk usage.

## Acceptance Criteria

- Selecting a running container's Stats view produces the stated measurements and charts.
- Leaving the view releases its continuous stream.
- Thirty minutes of viewing does not produce memory growth proportional to elapsed time.
- Counter reset/zero-delta/absent-field samples do not create invalid or falsely precise values.
- Health, exits, OOM, and restarts are visible when reported by the Engine.

## Verification

Metric evidence compares representative derived values with Docker CLI semantics, including memory cache accounting across relevant cgroup variants. Verify rate calculations, missing fields, reset/zero-delta boundaries, active-view stream lifetime, bounded history, and real container diagnostic states.
