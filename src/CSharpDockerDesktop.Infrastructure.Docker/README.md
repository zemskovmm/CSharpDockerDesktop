Docker Engine protocol, decoding, and platform transport implementations live here, independently of Uno. `DockerEngineConnectionClient` implements the Application connection contract with `System.Text.Json`, `HttpClient`/`SocketsHttpHandler`, and `NamedPipeClientStream`.

The client performs readiness, version discovery, API negotiation, Engine information retrieval and asynchronous retained-transport liveness. Its retained connection provides the Application `IContainerReader` capability for all-container listing and inspection; see [container acquisition and resource-schema evidence](../../docs/container-acquisition.md). See [connection contract and verification](../../docs/engine-connection.md). Production transport supports local Windows pipes only; the internal cross-platform fixture override is restricted to the test assembly. Discovery precedence, other resources and other live tools remain pending. The retained connection also provides borrowed `IContainerCommands` lifecycle operations; see [safe parameters, uncertainty, transport replay protection and compatibility evidence](../../docs/container-commands.md). The borrowed `IEngineEventSource` capability observes changes; see [event observations, lifetime, transport ownership and schema evidence](../../docs/engine-events.md).

The desktop composes this client through Application-owned `DesktopSession`. Successful connections support `CheckLivenessAsync` using `GET /_ping`. Negotiated pools refuse replacement pipes before they can carry requests, invalidating old metadata and requiring a fresh handshake. Events use one separately negotiated pool, so a legitimate concurrent stream does not change ordinary transport generation or starve resource reads. Replacement within either pool invalidates its observations. Application owns retry bursts, cooldowns, status publication, cancellation and disposal; protocol remains independent of Uno.

The borrowed `IContainerLogSource` capability uses independently negotiated, capped log pools, authoritative TTY inspection and bounded UTF-8/framing delivery. See [logs contract, budgets, cleanup and simulated evidence](../../docs/container-logs.md). DesktopSession and presentation integration are subsequent work.

The retained connection also provides borrowed `IImageReader` list/inspect reads through the shared bounded resource GET path. See [image projections, references, API 1.40–1.56 evidence and verification limits](../../docs/image-acquisition.md). Image session, event reconciliation, presentation and deletion integration remain subsequent work.

The retained connection provides borrowed `IImageCommands` for single-image non-force deletion, sharing container-command admission and sealed transport continuity. See [removal evidence, alias/parent consequences, uncertainty and API contract checks](../../docs/image-commands.md). Application operation coordination and deletion presentation integration remain subsequent work.

The retained connection provides borrowed `IVolumeReader` list/inspect reads with complete daemon names, retained list warnings and exact raw Inspect through the shared bounded resource reader. See [volume acquisition, supported API contracts and verification limits](../../docs/volume-acquisition.md). Volume session coordination, event reconciliation, presentation and deletion remain pending.

The retained connection provides borrowed `IVolumeDependencyReader` with fresh all-container filtering and exact inspected named-volume matching. See [volume dependency evidence, budgets, failure semantics and API contracts](../../docs/volume-dependencies.md). This capability adds no session coordination or deletion UI.

The retained connection provides borrowed `IVolumeCommands` for ordinary single-volume non-force deletion, sharing the existing container/image mutation admission and sealed retained transport. See [original-name handling, immutable outcomes, cancellation evidence and compatibility checks](../../docs/volume-commands.md). Volume session dependency prechecks, confirmation, operation reconciliation and deletion UI remain subsequent work.
