Docker Engine protocol, decoding, and platform transport implementations live here, independently of Uno. `DockerEngineConnectionClient` implements the Application connection contract with `System.Text.Json`, `HttpClient`/`SocketsHttpHandler`, and `NamedPipeClientStream`.

The client performs readiness, version discovery, API negotiation, Engine information retrieval and asynchronous retained-transport liveness. Its retained connection provides the Application `IContainerReader` capability for all-container listing and inspection; see [container acquisition and resource-schema evidence](../../docs/container-acquisition.md). See [connection contract and verification](../../docs/engine-connection.md). Production transport supports local Windows pipes only; the internal cross-platform fixture override is restricted to the test assembly. Discovery precedence, other resources, lifecycle operations and other streams remain pending. The retained connection now also provides the borrowed `IEngineEventSource` capability; see [event observations, lifetime, transport ownership and schema evidence](../../docs/engine-events.md).

The desktop composes this client through Application-owned `DesktopSession`. Successful connections support `CheckLivenessAsync` using `GET /_ping`. Pipe-open generation tracking invalidates old metadata on transparent HTTP reconnection and requires a fresh handshake. Events use one separately negotiated pool, so a legitimate concurrent stream does not change ordinary transport generation or starve resource reads. Replacement within either pool invalidates its observations. Application owns retry bursts, cooldowns, status publication, cancellation and disposal; protocol remains independent of Uno.
