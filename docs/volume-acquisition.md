# Read-only volume acquisition

The retained negotiated `DockerEngineConnection` supplies Application-owned `IVolumeReader` alongside container/image reads, commands, events, Logs and liveness. This capability is borrowed: obtaining it transfers no transport or disposal ownership. Domain projections have no Uno or protocol dependencies. Application-owned [volume browsing](volume-browsing.md) and [shared event reconciliation](volume-reconciliation.md) use this capability. Presentation, dependency acquisition and deletion remain pending.

## Requests and identities

Listing uses `GET /v{negotiated}/volumes` without filters, so it requests all daemon-visible volumes. Inspection uses `GET /v{negotiated}/volumes/{escaped-name}`. Both use the existing negotiated API and retained ordinary HTTP pool. Reads perform no mutation, registry access, filesystem browsing, automatic logging or diagnostic transmission, and add no negotiation.

The official read endpoint accepts a volume name or ID as a string. This client retains the complete daemon `Name` as authoritative identity, including plugin/cluster names. It does not interpret hexadecimal prefixes, image tags/digests, or impose the local driver's creation-name grammar. Request preflight rejects null/empty/whitespace-only names, names exceeding the client safety bound of 4096 UTF-16 code units, control characters, unmatched UTF-16 surrogates and the exact dot segments `.` and `..`. The same usability check applies to returned identity. Other accepted characters, including Unicode, whitespace within or around a nonempty name, slashes, backslashes, percent signs, query/fragment punctuation and colons, remain unchanged. `Uri.EscapeDataString` encodes the entire original accepted name as one path component. No trim, truncation, unescape, path splitting or normalization occurs. The returned name is authoritative even if it differs from the requested reference.

## Metadata, warnings and raw Inspect

`VolumeSummary` and `VolumeInspection` project available name, driver, scope, mountpoint and labels. Missing/null display fields mean unavailable; empty strings and empty label maps remain valid empty metadata. Label values follow the schema's string contract, including empty strings; wrong types and null label values fail as malformed data. Unrecognized scope strings remain available metadata rather than breaking additive compatibility. Missing/unusable identity, incompatible selected field types, invalid selected Unicode and duplicate selected fields/label keys fail as malformed data. Unknown fields, including driver Status, Options, usage information and ClusterVolume, are tolerated and retained in raw Inspect.

The list response is an object, not an array. `VolumeListing` independently retains nullable `Volumes` and nullable `Warnings`. Missing/null collections are unavailable and are never fabricated as empty arrays; valid empty arrays remain empty. The official warning contract describes problems encountered fetching volumes. Every warning string is preserved verbatim in daemon order, including duplicates and empty strings. `HasWarnings` is true whenever any warning entries exist, even when Volumes is null/empty. Such a result carries problematic-listing evidence; future browsing consumers must present that evidence and must not reduce it to an ordinary empty success. Warnings are sensitive daemon content, not routine diagnostics. Invalid warning container/item types fail instead of silently dropping warnings.

Returned records and collection/dictionary wrappers are immutable. `VolumeInspection.RawJson` independently retains the exact actual UTF-8 response text, including whitespace, unknown fields, sensitive driver options/status, numeric lexemes and trailing whitespace. It is not reconstructed from selected metadata. Invalid raw UTF-8 is rejected rather than replaced with substitute characters. No metadata or raw response is automatically logged or transmitted.

## Official API evidence

Every official Docker API YAML from 1.40 through 1.56 was retrieved and inspected on 2026-10-14. [The baseline schema](https://docs.docker.com/reference/api/engine/version/v1.40.yaml) and [current supported schema](https://docs.docker.com/reference/api/engine/version/v1.56.yaml) define the list object with volume and string-warning arrays, the inspect volume object, and a required string name/ID path parameter. The list endpoint declares 200/500 responses; inspect declares 200/404/500 responses. Both use the ordinary ErrorResponse message contract. The optional list filters parameter is not used. Selected volume field types remain stable across all 17 schemas; ClusterVolume becomes an additive volume property in API 1.42.

`tests/CSharpDockerDesktop.Connection.Tests/Fixtures/Volumes/schema-evidence.json` records each source URL, SHA-256, retrieval date, field types, label/warning item contracts, request parameters, response codes and response-schema references. Adjacent versioned list/inspect fixtures are representative synthetic responses derived from those schema examples/types, with synthetic warnings and sensitive/additive values. They are not captured daemon responses. The harness negotiates and decodes all 17 versions and asserts exact negotiated paths and full names. The tested API maximum remains 1.56.

## Lifetime, budgets and failures

Volumes reuse `DockerResourceReader` without changing existing resource behavior: asynchronous header/body I/O, off-caller-thread parsing, configured request deadlines and success/error byte limits, linked caller/connection cancellation, and cleanup of request, response and body stream on terminal paths. Cancellation and transport generation are fenced before dispatch, after headers/body and after decoding so late results cannot publish success after cancellation, expiry, disposal or transport replacement.

Caller cancellation throws normal `OperationCanceledException`, including transport-wrapped cancellation. HTTP 404 is NotFound; 409/304 Conflict; 401/403 AccessDenied; other 4xx InvalidRequest; other unsuccessful statuses DaemonFailure. Unauthorized transport access is AccessDenied. Interrupted/disposed/stale-generation/deadline reads are TransportLoss; a call begun after owner disposal throws ObjectDisposedException. Oversized success or malformed selected JSON is MalformedData. Oversized error bodies preserve HTTP classification without retaining a truncated message. Original JSON `message` or non-JSON error text remains separate from fixed safe descriptions and is never automatically printed. Reads never dispose the borrowed connection or live subscriptions.

## Verification evidence and limits

The dependency-free executable harness covers API 1.40–1.56 negotiation and schema fixtures, full names and safe path escaping, pre-dispatch validation, authoritative metadata, immutable collections, exact sensitive/additive raw Inspect, missing/null/empty metadata and collections, warnings with normal/empty/null volumes, malformed/additive fields, Unicode, HTTP/permission classifications and daemon messages, known/unknown-length byte limits, exact budget boundaries, caller cancellation before dispatch and during headers/bodies, wrapped cancellation, deadlines, owner disposal and repeated cleanup. Deliberately non-cooperative header/body fixtures verify late valid results cannot publish after caller cancellation, disposal or expiry. Controlled decoder hooks exercise the final publication fence for both list and inspect under lifetime cancellation and transport-generation changes.

The simultaneous named-pipe fixture uses real SocketsHttpHandler with synthetic HTTP servers and keeps volume/container/image reads, container/image commands, events, Logs and liveness on one retained connection. Live streams stay active through volume reads, and reads/liveness continue after subscriptions close. Exactly three existing independent handshakes remain (ordinary requests, Logs, events); volume acquisition adds none.

On 2026-10-14, the executable harness passed **170/170 groups on macOS 26.7.1 with .NET SDK 10.0.402**. The Debug solution build succeeded with no errors and one existing Uno ServerProcessorGenerator CS8785 development-generator warning. The Release solution build succeeded with zero warnings/errors. No `.idd/verification.yaml` exists; verification follows the established executable harness and full solution builds.

Controlled HTTP handlers and synthetic named-pipe servers establish protocol, cleanup, bounds and coexistence behavior under simulation. These results do not establish real Windows named-pipe ACLs, Docker Desktop/WSL2 volume/driver behavior, Windows delivery or workstation performance targets. Real Windows/Docker evidence remains outstanding.
