# Container event reconciliation

DesktopSession owns container synchronization in the Application layer. It borrows IEngineEventSource and IContainerReader from the same negotiated connection, owns at most one subscription, and retains ownership of connection disposal. Presentation continues to observe IContainerBrowser snapshots and notifications; it does not read Docker events or issue protocol requests. Images share this same observation subscription and cursor through their independent Application scheduler, as documented in [image browsing](image-browsing.md). Volumes, Networks, mutations, logs, terminal and stats are separate capabilities.

Observation opens before the initial complete container list. A manual refresh during opening waits for that initial observation attempt too. Once observation opens, consumption runs concurrently with the serialized authoritative read queue. If opening fails without transport loss, browsing starts with a visible classified observation diagnostic. The opening deadline unlocks bounded fallback browsing even for an opener that ignores cancellation; the owner still joins its eventual result before connection release. Observations before or during the initial snapshot leave a pending invalidation that is reconciled after the snapshot, including when an observation was consumed before the list request started. Events never create rows or patch name, health, status or other properties; list and inspection results remain authoritative.

## Bounded work and details

The Infrastructure subscription uses its bounded event channel and producer backpressure. Application retains no event history, actor attributes, action collection or per-resource backlog. It keeps one pending list flag, one pending currently requested detail flag, one capacity-one wake signal, and one timestamp cursor. Repeated timestamps, duplicate observations, unknown container actions and missing/empty resource identities are synchronization observations. Missing identity invalidates requested details conservatively. Image observations invalidate the independent image scheduler and can advance the same cursor, without scheduling container work. Unknown resource types can advance a valid timestamp cursor but do not schedule either resource family.

Event requests leave active reads running so a busy stream cannot repeatedly cancel I/O and prevent progress. Events during an active read leave subsequent reconciliation pending. A configurable batching interval coalesces list requests. Requested details receive a turn after a list even if more list invalidations arrive, keeping actual I/O concurrency at one. A selected-resource observation immediately clears exposed detail/Inspect content. If another observation arrives during inspection, that successful read does not resurrect invalidated content; a subsequent authoritative read supplies it. The authoritative list removes missing selections and pending detail requests, and inspection NotFound removes its stale row. Closing/clearing details cancels that request and leaves NotRequested, which background observation never reopens. Explicit refresh and navigation retain their existing latest-request cancellation behavior.

ContainerReconciliationOptions supplies independently validated implementation defaults: a 100 ms list batch interval, yielding consumption after 128 observations, two-second replay overlap, three-second observation retry delay, six attempts before a 30-second cooldown. Zero attempts disables automatic observation recovery. These values are configurable tuning defaults, not product latency or delivery promises. Short-operation deadlines remain governed by ConnectionRecoveryOptions. Long-running observation has lifetime cancellation rather than an ordinary request deadline.

## Recovery and ownership

Every negotiated connection gets a fresh empty browsing generation and a complete snapshot. A valid previous high-water timestamp can supply an overlapped since cursor only for the same endpoint and observed Engine ID, with honest null identities compared as null. The cursor retains nanoseconds as integers, ignores invalid/older timestamp candidates, and never deduplicates events by time. Fractional overlap subtraction also preserves precision. Replay is not assumed to be complete; concurrent observations are reconciled after the complete reconnect snapshot.

Subscription opening and completion failures remain explicit EngineEventFailure diagnostics. Null completion without session cancellation is classified as UnexpectedEnd. The subscription is disposed before a replacement attempt. Non-transport failures retain manual browsing/navigation and schedule bounded retries with cooldown; successful reopening clears the diagnostic and requests authoritative reconciliation because observations may have been missed. The shell displays the classification and a fixed description; the original bounded daemon message remains available only through the deliberate existing Show daemon message action.

Event TransportLoss invalidates container state and participates in the existing connection recovery workflow, requiring fresh negotiation. Retry, generation replacement, continuity loss and shutdown cancel and join event opening/consumption, batching/recovery waits, and outstanding reads before connection disposal. Even a source or reader that completes after cancellation is awaited, owned and rejected for publication into the replacement session. No event metadata, actor attributes, daemon messages or raw Inspect is automatically logged or persisted.

## Recorded evidence and limitations

On 2026-10-14 the independent net10.0 harness passed **63/63 groups on macOS 26.7.1 with .NET SDK 10.0.402**. The complete Uno desktop solution built with zero warnings/errors. Nine reconciliation groups use controlled subscriptions, controlled delay advancement, and authoritative readers, including readers/openings deliberately completing after cancellation. They cover observations before/during/after the first snapshot, duplicate high-resolution timestamps, 6,000 sustained observations with bounded pending work and detail fairness, unknown actions/missing identity, external deletion during inspection, close races, precise overlap, changed Engine identity, full reconnect resync, all opening failure classifications, unexpected completion and cooldown recovery, opening deadlines, cancellation, joined disposal and event continuity loss during outstanding list/inspection reads.

The automatic-presentation check connects the actual ContainerBrowserView and JsonInspectView to DesktopSession. It verifies that authoritative automatic changes update rows, an observation clears stale Inspect immediately, and external deletion clears selection, detail and Inspect without a user refresh. Existing resource, transport, schema, connection, presentation and Inspect groups remain included.

These event subscriptions and daemon states are simulated deterministic evidence, not captured real Docker operations. Existing controlled cross-platform named-pipe tests exercise production protocol/stream primitives separately. This Mac host does not establish real Windows Win32 startup/interaction, non-elevated pipe ACL access, Docker Desktop/WSL2 events, external CLI convergence, actual daemon restart/replay, alternate daemon compatibility or measured performance targets. Record those on a Windows host with its actual daemon/backend and workload before claiming runtime acceptance. No such Windows daemon evidence was available for this change.
