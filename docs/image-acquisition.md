# Read-only image acquisition

The retained `DockerEngineConnection` supplies Application-owned `IImageReader` alongside the existing container, events, command and Logs capabilities. The owner controls connection disposal; acquiring an image reader transfers no ownership. Domain projections contain no Uno or transport dependencies. Protocol acquisition now feeds the [Application image browsing session](image-browsing.md); image presentation, automatic image-event reconciliation and deletion remain subsequent work.

Listing uses `GET /v{negotiated}/images/json?all=true&digests=true`: intermediate images are included, available repository tags and digests are retained verbatim, and identity is the complete daemon ID. Inspect uses `GET /v{negotiated}/images/{escaped-reference}/json` with no platform/manifests/identity options. Metadata is therefore the daemon's default image inspection, not an inferred merge of every platform in a manifest index. No independent negotiation, registry access or mutation occurs.

References accept bare image IDs (including hexadecimal prefixes), algorithm-qualified digests, repository names, optional registry hosts/ports (including bracketed IPv6), tags and repository digest references. Preflight uses the ASCII [Docker distribution reference grammar](https://github.com/distribution/reference/blob/main/regexp.go), with a 255-character repository-name bound and a 4096-character overall bound. Empty input, malformed separators, whitespace, controls, URL/query/fragment syntax, percent escapes, backslashes, path traversal and overlong tags/names are rejected before transport work. Digest syntax is checked; daemon-supported algorithms, digest length semantics, normalization and existence are left to the daemon. The entire original reference is encoded with `Uri.EscapeDataString` as one path component, without truncation, unescaping or splitting it into paths. The daemon's returned identity is authoritative, including when the requested name/tag is an alias.

`ImageSummary` retains repository references, Unix creation time and `Size` as nullable signed 64-bit metadata. Size must be nonnegative; zero is valid. Missing/null collections are unavailable, while empty arrays remain empty. Historical `<none>` reference placeholders are retained as delivered rather than replaced with invented names. Creation zero in a list is the Unix epoch. Inspect's historical Go zero creation timestamp means unavailable, matching omission/null in newer schemas; real timestamps preserve their offset with .NET's available timestamp precision. The exact source preserves finer fractional precision.

Inspect projects available OS/OS version, architecture/variant, tags/digests, size, image `Config` and `RootFS` layer digests in daemon order. Configuration exposes user, environment, command, entrypoint, working directory, labels, exposed ports, volumes, OnBuild, stop signal, shell and ArgsEscaped. Null/missing differ from valid empty values, empty configuration/root objects and false. The configuration source substring retains all other fields, such as Healthcheck. Neither deprecated `ContainerConfig` nor `VirtualSize` supplies fallback metadata. Read results use immutable records and read-only collection/dictionary wrappers. `RawJson` retains the exact UTF-8 inspect text, including whitespace, unknown fields, sensitive values and number lexemes; it is not reconstructed from projections. Configuration and inspect content are never logged.

## Supported schema evidence

Every official [Docker API YAML](https://docs.docker.com/reference/api/engine/version/v1.56.yaml) for 1.40–1.56 was read on 2026-10-14. `tests/CSharpDockerDesktop.Connection.Tests/Fixtures/Images/schema-evidence.json` records each version's source URL and SHA-256, list/inspect/config field types and query parameters. The adjacent list, inspect and minimal-inspect fixtures are synthetic representative responses built from official schema field examples/types. Sensitive, future and unknown values are synthetic test data. These are not captured daemon responses. The executable harness negotiates and decodes all 17 versions; API maximum 1.56 remains backed by image evidence in addition to the existing connection/container/events/Logs contracts.

The [official API history](https://docs.docker.com/reference/api/engine/version-history/) and schemas establish these relevant changes:

| API | Image read compatibility evidence |
| --- | --- |
| 1.40–1.42 | Baseline Id/repository arrays, integer list Created, string inspect Created, Size, Config, OS/architecture and RootFS; legacy fields are optional to this client. |
| 1.43 | Untagged list references become empty arrays instead of `<none>` placeholders. |
| 1.44 | VirtualSize is omitted; absent inspect creation time can be omitted instead of Go zero time. |
| 1.45–1.46 | Container/ContainerConfig removed; extra container-only Config fields deprecated. |
| 1.47–1.49 | Additive manifests/descriptor fields and optional inspect selection parameters are tolerated; no selection parameter is requested. |
| 1.50–1.52 | Container-only Config fields removed; unset configuration and legacy metadata may be omitted. Container usage count behavior changes but this projection does not depend on that field. |
| 1.53–1.56 | Inspect Identity and optional list identity enrichment are additive. Attestations are a separate endpoint. Baseline read fields remain compatible. |

Selected fields with wrong JSON types, missing/empty identity, invalid timestamps or out-of-range numbers fail as malformed data. Unknown fields, including unknown platform/identity structures, do not invalidate the supported projection and survive in raw Inspect. The schemas sometimes mark list fields required; this client conservatively treats absent optional display metadata as unavailable rather than synthesizing values. It does require usable identity.

## Lifetime, budgets and failures

`DockerResourceReader` is the small shared extraction of the prior container GET reader. Container paths, decoding, defaults and failure descriptions remain unchanged. Images use the same configured request deadline and success/error response-byte limit, linked caller/connection cancellation, asynchronous header/body I/O and off-thread decoding. Requests, responses and body streams are released on all terminal paths. Success is fenced before dispatch, after headers/body and after decoding against cancellation and the original transport generation. A silently replaced retained transport returns transport loss and cannot establish an image result from stale negotiated metadata.

HTTP 404 is NotFound, 409/304 Conflict, 401/403 AccessDenied, other 4xx InvalidRequest, and other unsuccessful statuses DaemonFailure. Unauthorized transport errors remain AccessDenied; interruption, disposal, generation loss and deadlines return TransportLoss. Caller cancellation throws normal `OperationCanceledException`, including wrapped transport cancellation. Original JSON `message` or non-JSON error text is retained separately from a safe fixed description and is never printed automatically. Oversized error bodies preserve HTTP classification without retaining truncated content; invalid JSON success bodies and oversized success bodies are MalformedData. Borrowed calls do not close the connection or change stream ownership.

## Verification evidence

The dependency-free executable connection harness covers negotiated 1.40–1.56 endpoint paths, image reference escaping/invalid preflight, complete authoritative projections, read-only collections, exact sensitive/unknown raw Inspect, historical/current omissions and placeholders, null/empty/zero metadata, malformed known fields and numeric/timestamp bounds, known/unknown-length oversized success/error bodies, daemon message preservation, permission/HTTP classifications, cancellation before dispatch/during headers/during bodies, request deadlines, repeated disposal and generation changes before/after headers/body/decoding. Deliberately non-cooperative header/body fixtures verify late data cannot publish success after caller cancellation, connection disposal or expiry. A deterministic shared-decoder check verifies its final cancellation/generation publication fence.

The simultaneous named-pipe fixture now performs image list/inspect while container Logs and Engine events remain live, then closes both borrowed subscriptions and confirms image/container reads and retained liveness still work. Exactly three independent handshakes (ordinary, Logs and events pools) remain; image reads add no negotiation. Existing container, reconciliation, lifecycle, Logs and presentation tests continue to run.

On 2026-10-14, the executable harness passed **111/111 groups on macOS 26.7.1 with .NET SDK 10.0.402**. The full solution built with zero warnings/errors. Verification used the repository's existing executable harness and solution build; no external Docker daemon or GUI was needed.

These checks use controlled HTTP handlers and real `SocketsHttpHandler` over synthetic named-pipe servers on macOS. They establish protocol/cleanup/coexistence behavior under simulation. They do not establish real Windows named-pipe ACLs, Docker Desktop/WSL2 image behavior, Windows delivery, or workstation performance targets. Real Windows daemon evidence remains outstanding.
