# Application volume browsing

`DesktopSession` implements `IVolumeBrowser` using the borrowed `IVolumeReader` on its retained negotiated connection. Initial connection and every replacement/reconnect start a fresh volume list without another connection or negotiation. A missing reader produces Unavailable list/detail state. Snapshots stay in memory and are discarded on connection loss, replacement, disconnect or disposal. Initial reads wait for the shared Engine observation to open or reach its bounded fallback. Volume observations invalidate authoritative list/detail work through that same subscription; see [volume reconciliation](volume-reconciliation.md). This boundary is read-only; the desktop presentation described below consumes it. Dependency acquisition and deletion remain separate work.

Consumers read `VolumeSnapshot` after `VolumesChanged`, which may arrive off the UI thread. The snapshot carries the connection generation, complete selected name, immutable useful rows, exact latest accepted listing, list/detail states, inspection metadata and exact `RawJson`, and separate classified list/detail failures. Names use ordinal identity without normalization, prefix matching or shortening. Rows are deduplicated by that identity. Labels, rows and warnings are defensively copied into read-only collections, including results supplied by mutable capability implementations. Null metadata/labels remain unavailable; empty metadata and collections remain available empty values. Raw inspection and original daemon messages remain sensitive data and are never automatically logged or transmitted.

## Listing evidence and retained data

`Volumes` is the useful browsing collection. `LatestListing` is the exact most recent accepted successful read, with original collection order and warnings; it is not rewritten to match retained rows or an Inspect NotFound result. `Warnings` projects its warnings without changing null, empty, ordering, duplicates, whitespace or content. `Completeness`, `HasRetainedRows` and `IsAuthoritative` distinguish current complete state from incomplete or stale evidence. Ready describes completion of an available list read and is insufficient by itself to establish completeness.

| Read outcome | State / completeness | Useful rows and selection |
| --- | --- | --- |
| Non-null Volumes, no warnings (null or empty Warnings) | Ready / Complete; IsAuthoritative | Replace useful rows. Preserve selected complete name if present; otherwise clear selection and raw details. An empty collection is authoritative successful emptiness. |
| Non-null Volumes and one or more warnings | Ready / Incomplete; HasWarnings | Update/add returned names, retain previous names omitted from the response. Retained names set HasRetainedRows. Even an empty warning-bearing collection is not authoritative absence. Preserve selection and useful details. |
| Null Volumes, with any warning representation | Unavailable / Unavailable | Retain useful rows and selection; mark retained rows. Preserve the null collection and exact warnings in LatestListing. Never infer absence. |
| Refresh pending | Loading / Unavailable | Retain useful rows, previous listing/warnings and valid selection; mark retained rows. Previous completed inspection can remain useful. Fence an active inspection and reload it only if still requested. |
| Non-transport read failure | Failed / Unavailable | Retain useful rows, selection and latest accepted listing/warnings; mark retained rows. Preserve the original classified failure, HTTP status and daemon message separately from its safe description. No reconnection. |
| Shared connection invalidation | Unavailable / Unavailable | Clear rows, listing/warnings, selection and raw detail. A fresh generation starts with no cached resource data. |

An initial null listing has no useful rows but still differs from an authoritative empty listing. Partial responses never accumulate warning history: a new accepted successful listing replaces the warning collection exactly, including null and empty. Pending refresh and failure retain the latest accepted warnings because no newer listing has established replacement evidence.

Selection admits only a complete name in current usable rows, including explicitly retained rows under incomplete evidence. Invalid or null selection clears detail; selecting the same identity preserves existing or explicitly cleared detail. Selection changes, explicit inspection refresh and clearing increment the detail revision, cancel/supersede old detail work and immediately clear exposed raw JSON. Clearing retains the selected name and NotRequested state; list refresh does not reopen explicitly cleared inspection. A current successful inspection must return the exact selected name; a different identity becomes MalformedData and its raw data is never attached to the selection. A current Inspect NotFound removes that useful row, clears selection/raw detail and retains its classified failure. Superseded NotFound cannot remove newer state.

## Scheduling, recovery and lifetime

The Application coordinator has one volume worker, a capacity-one wake-up channel and one pending flag per manual list/event list/detail family. Event-driven lists use the existing configurable reconciliation batch interval; repeated observations do not repeatedly cancel active I/O. Reads are serialized; repeated requests coalesce. When both families are pending, successive turns alternate so refresh bursts and selection bursts cannot monopolize the worker. List refresh supersedes earlier list and detail publications; selection changes supersede detail without canceling active list I/O. Requests run asynchronously with an explicit deadline and cancellation. A separate deadline remains active when a superseded reader ignores cancellation.

Connection identity, list/detail revisions, selected name, cancellation and deadline state fence both successful and failed publications. A volume transport-loss response or deadline clears all shared resource state and cancels Containers, Images, events, lifecycle/image commands and relevant Logs. It signals the existing connection owner; volume browsing has no reconnect loop. Loss originating from each of those shared capabilities or liveness also invalidates volume state and notifies its observers. Shared connection identity is fenced before cancellation callbacks run. Image-command transport-loss notification now reaches every browser immediately.

Replacement, disconnect and disposal invalidate publication before cancellation and asynchronously join all owned volume work before releasing the retained connection. A non-cooperative reader must finish before connection disposal or recovery can obtain a replacement. Its deadline still makes exposed state unavailable promptly while the join is pending. Repeated disconnect/disposal calls join the same owned work; shutdown does not create overlapping connections or resurrect late raw data. Slow I/O does not synchronously block the UI. Observer exceptions do not orphan volume work and are not logged.

## Read-only volume presentation

The shell's Volumes page consumes only `IVolumeBrowser`; it makes no Docker protocol calls. The finite `ItemsStackPanel` table recycles visual rows and searches loaded complete names, driver, scope, mountpoint, label keys and label values away from the UI thread. Obsolete searches cancel and cannot replace a later query, source collection, connection generation or page lifetime. Case-insensitive substring search is only discovery: selection, opening and deliberate Copy full name use the entire ordinal name without trimming, normalization, shortening or prefix matching. Table metadata previews are bounded; Overview and Inspect expose the complete values. Null scalar/label data is explicitly unavailable; empty strings and empty label collections have distinct text. Mountpoints are read-only metadata, without filesystem browsing.

The page distinguishes complete authoritative results, incomplete results, unavailable listing evidence, refreshing and failed reads. Only a complete authoritative accepted empty collection says there are no volumes. The latest successful listing and the useful retained browsing collection remain separate evidence. Warning-bearing empty lists and null collections cannot prove absence. Retained rows, exact selection and completed details remain usable through incomplete/null listings, refresh and non-transport failures while the Application connection remains usable. A null collection's `Unavailable` state alone does not clear the page or disable refresh. Complete-list disappearance and current Inspect NotFound follow Application's cleared selection and preserve the classified failure; connection invalidation or generation replacement clears old content.

Overview is built asynchronously for the exact current name, inspection object and connection generation. Inspect reuses `JsonInspectView` for formatted virtualized nodes, collapsed-content search, expansion/collapse, duplicate-name-aware paths, and deliberate path/exact-source-value copy. Unknown fields, precise numeric lexemes, whitespace, duplicates, null/empty collections and sensitive fields remain actual daemon data. Shared Inspect getters now also hide content immediately when the owner's live current-content predicate rejects it, before a queued invalidation notification is applied. Copy admission and pending parsing/Overview/filter/copy callbacks re-read live state; selected-volume event invalidation hides obsolete content and cannot publish it later.

Warning existence and count are visible without revealing private text. The deliberate Show daemon warnings and original messages control prepares a read-only evidence panel asynchronously. It preserves order, duplicates and the original warning/message text, including whitespace; numbered entries with character counts distinguish empty strings, null entries, empty collections and unavailable null collections. Classified list/inspection failures and HTTP status remain readable without original daemon content. A new accepted listing replaces warnings exactly rather than accumulating history; new warning/failure evidence resets reveal and fences a pending reveal. Refresh/failure retain previous accepted warnings until replacement evidence exists. Current connection-loss originals can also be deliberately revealed. Original data is not logged, uploaded or automatically copied.

Notifications may arrive off-thread and coalesce to one UI callback reading the latest immutable snapshot. Attachment epochs fence old callbacks across repeated attach/detach. Navigation and disposal cancel presentation work, clear raw content, detach notifications and clear owned Application inspection without disconnecting the shared session. Closing details retains the table's selected name; re-opening the same name explicitly refreshes Application's cleared inspection. Teardown does not clear a replacement generation's or another selection's inspection. Containers, Images, lifecycle actions and Logs retain their existing contracts. The page has no Delete action or dependency assumptions.

Tab reaches resource/Inspect search, refresh, open/back, reveal and deliberate copy controls; arrows select rows and Enter opens Overview. Escape closes details, with selected-row focus/scroll restoration. Inspect has keyboard expansion/collapse using Right/Left and Enter. F3/F5 are additional search/refresh bindings; native function-key behavior remains platform-dependent and is not established by the Mac fixture. Spelling correction is disabled for search fields; native prediction support remains a platform validation limit.
