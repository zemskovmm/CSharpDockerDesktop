# Application image browsing

`DesktopSession` implements `IImageBrowser` using the `IImageReader` borrowed from its retained, negotiated Engine connection. It owns the image scheduler and cancellation lifetime, while the connection/recovery owner remains responsible for transport disposal and negotiation. Image work neither disposes the borrowed reader nor opens another connection. Containers, events, lifecycle commands and Logs keep their existing capabilities and coordination.

`ImageBrowsingSnapshot` is immutable in-memory state scoped to the same connection generation as container browsing. It distinguishes unavailable capability/disconnection, loading, a successful empty list, ready rows and a classified failure. Inspection has independent state and failure data. Rows retain complete authoritative image IDs and all Domain metadata; duplicate IDs collapse to one row. Selection accepts only a complete ID present in current rows, and Inspect requests use that ID rather than a repository tag. A successful list proving absence clears the selection and inspection; current Inspect NotFound removes the stale row, clears selection/content and preserves the inspection failure classification. Clear inspection cancels detail work while retaining a valid selection. No image data is persisted.

The single image worker serializes list and Inspect I/O. A capacity-one wakeup channel and bounded manual-list, event-list and requested-detail flags coalesce bursts; revision and cancellation fences reject superseded results even from non-cooperative readers. Scheduling alternates list and detail when both are pending so either request family gets a turn. A newer list refresh fences earlier detail work; selection changes fence only detail requests so list I/O can still progress. Continuous supersession can prevent obsolete results from publishing, but cannot create unbounded requests or concurrent image reads. Consumers receive change notifications that can originate off the UI thread, read the latest snapshot and marshal it for display. Shared container notifications emit an image notification only when its snapshot changed.

Each negotiated connection/reconnect starts an authoritative image list after the shared event observation attempt opens or reaches its bounded fallback. Image transport loss or a current request deadline invalidates both resource snapshots and cancels container reads, event observation, lifecycle work and relevant Logs immediately. The existing connection owner performs recovery. Container/event/operation/Logs transport loss and liveness loss also invalidate image state. Original daemon messages remain separate from safe failure descriptions; non-transport image failures do not initiate reconnection. Neither configuration, raw Inspect nor daemon messages are automatically logged.

Replacement, disconnect and disposal fence publications before cancellation, then join all owned image and container/session work before disposing the retained connection. A reader that ignores cancellation must return before the owner can release that connection; deadlines still invalidate exposed state and signal recovery while that join is pending. The join is asynchronous and does not block UI interaction.

The image browsing boundary remains read-only. Session-owned deletion is exposed separately through [IImageOperations](image-operations.md), without registry interaction. The desktop presentation described below consumes its snapshots; raw Inspect remains the exact Domain JSON, including sensitive and unknown values, for deliberate display/copy.

## Shared image observation

Images use the connection owner's existing single Engine event subscription, never a second subscription or connection. The initial image scheduler waits for observation establishment. A classified non-transport opening failure starts manual browsing; the opening deadline also unlocks a fallback snapshot even if an opener ignores cancellation. That late opening remains owned and must return before connection release. A bounded flag on the shared coordinator bridges observations consumed before the image coordinator is created. Initial loading preserves that flag through its first snapshot; observations before or during loading cause a subsequent authoritative reread.

Every image action, including tag, untag, delete and unknown actions, invalidates the image list. Observations never insert, remove or patch rows, and no event attributes, resource metadata or event history are retained. Duplicate observations and equal timestamps remain valid invalidations. Unknown resource types keep the shared cursor behavior without scheduling resource reads. Image and container invalidation are independent; image events do not interrupt container list/Inspect, lifecycle operations or Logs.

An image event matching the selected full identity immediately clears exposed requested Inspect content, increments the detail revision and schedules an authoritative replacement. Missing or empty actor identity invalidates requested detail conservatively. An event during Inspect fences both stale successful and failed results, including a non-cooperative reader. Explicitly cleared inspection remains NotRequested. Current list absence or current Inspect NotFound clears the selection and detail; event action or identity alone is never disappearance evidence. Replacements preserve complete image IDs and the exact raw Inspect JSON.

Event list refreshes use the existing configurable reconciliation batch interval. Repeated invalidation neither cancels active event-triggered reads nor causes a request or notification per observation. A completed list can publish useful authoritative state while another list is pending; requested details receive alternating turns under a sustained stream. Only the first invalidation clears exposed Inspect and notifies consumers. Manual refresh retains its cancellation and revision behavior. An event-invalidated active request still has a deadline: event supersession cannot silently disable connection recovery for a stuck reader.

Reopening observation requests fresh image state and invalidates selected requested details because continuity may have been lost. Observations around that snapshot leave another reread pending. Reconnect uses the shared exact integer cursor, fractional replay overlap and endpoint/Engine identity fence, followed by a fresh image generation and complete snapshot. Non-transport observation failure leaves manual browsing usable through the existing classified retry/cooldown policy. Transport continuity loss uses the existing connection owner and cancels all borrowed capability work. Disconnect, replacement and disposal fence publication first, then join image reads and shared observation opening/consumption/disposal before releasing the connection. No event attributes, resource metadata, raw inspection or original daemon messages are automatically logged.

## Desktop Images browser

Images navigation opens a dedicated virtualized page backed by `IImageBrowser` and the separate `IImageOperations` Application capability. Rows display every available tag/name, the shortened digest identity, creation time and byte size. Missing metadata is `unknown`; an available empty tag collection is `none`, and a reported zero size remains zero. The full authoritative image ID remains the identity for selection, intentional copying and opening details. Search covers loaded tags, repository digests, full IDs, creation timestamps and sizes with cancellation and revision fencing. Filtering and rendering initiate no Engine operations. Reordering or filtering preserves the selected full identity without initiating another inspection.

The page distinguishes not requested, initial loading, refreshing with previous rows, successful empty results, no search matches, classified refresh failure and disconnected capability. Errors show safe descriptions and available HTTP status without automatically exposing original daemon messages. Search, refresh, list selection, opening details and closing details are keyboard accessible through ordinary controls. Enter opens the selected image; Escape closes details while keyboard focus is within the page. Focus returns to the browser after closing and remains in Inspect during background node expansion.

Overview is prepared on cancellable background work and presents the authoritative image identity/references, timestamps/size, available OS/version, architecture/variant, configuration and ordered RootFS layer digests. Missing configuration, fields and layer collections are explicitly unknown; available empty collections are none. Configuration can contain sensitive values. Overview is a projection, while Inspect reuses the existing exact-source JSON viewer independently. Inspect supports searching collapsed names/values, keyboard expansion/collapse, duplicate-property-aware paths, deliberate path copying and exact source-slice value copying. Unknown fields, sensitive strings, whitespace, numeric lexemes and duplicate property names remain intact in copied values.

Image notifications can originate off-thread. The page coalesces bursts on the UI dispatcher and reads the latest snapshot when applying them. Page lifetime, connection generation, selected identity and current inspection/source guard all background Overview/filter/Inspect publications and copy admission. A selected-image event's loading snapshot clears exposed Inspect/Overview and disables content copying when applied; current-session guards reject stale copy or parse results even before its queued notification drains. Disappearance, external session-selection replacement and disconnect remove stale detail. Navigation/teardown detach image notifications, cancel page-owned work and clear raw Inspect, while the shared DesktopSession and other resource capabilities remain owned by the application shell. Closing details clears the Application-owned image inspection without disposing the shared session.

Image deletion consumes the [session operation contract](image-operations.md), as described below. The page provides no force deletion, registry interaction, Pull/Push or hidden mutations.

### Image deletion presentation

Delete image is available for a current selection in both the table and details. Tab reaches the controls; Delete within the page (outside an editable search box) opens confirmation. The dialog captures an immutable request with the complete authoritative ID and connection generation and displays that ID, identifying tags/names and `force=false`. It explains irreversible deletion, possible dependencies, the daemon's final decision, and that the client will neither remove dependent containers nor escalate to force. Cancel is the default button; Enter on initial dialog focus cancels. Cancellation restores the invoking control when available, otherwise the current details/browser focus.

The actual view re-reads Application state before capture and acceptance, including before queued notifications drain. A missing target, changed selection/generation, unavailable or non-ready list, obsolete dialog, detached view, or pending submission rejects dispatch. Confirmation is consumed before coordinator submission, including synchronous/reentrant notifications. One command is admitted without a page cancellation token; navigation neither cancels that command nor reconciliation. Both image and operation notifications share the existing capacity-one UI dispatch/lifetime fence. Teardown detaches subscriptions, clears exposed sensitive content and rejects late completions. Reentry reads the session's retained operation without replaying it.

A separate, scrollable operation panel stays visible with either browser or details. It retains target identity, command pending/reconciliation/completion, command classification and HTTP status, observation classification/generation, observed absence/presence, not-dispatched and unresolved outcomes. Command acknowledgement and removal-response record counts remain command evidence; authoritative absence does not establish which action caused it. Conflicts explain dependencies and discourage blind retries without suggesting force or container removal. Unresolved mutations are never automatically replayed. Admission feedback is separate and cannot overwrite retained useful evidence. Original daemon messages and removal records are hidden until deliberate reveal, can be hidden again, and reset to hidden for a new operation. Confirmation tags and sensitive evidence display are bounded to 16,384 content characters and 128 references/records, with explicit truncation notices; retained Application evidence is unchanged.
