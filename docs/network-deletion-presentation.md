# Network deletion presentation

`NetworkBrowserView` and `NetworksPage` consume the Application-owned `INetworkDeletionPreparation` and `INetworkOperations` services. Presentation never obtains a Docker connection or dispatches protocol requests. Accepted ordinary deletion and authoritative reconciliation remain owned by `DesktopSession` after page detach, navigation or selection changes. Reopening Networks discovers the retained operation independently of the current selection.

## Captured preparation and confirmation

List and detail Delete buttons and the Delete key (outside editable text) start a fresh asynchronous preparation for the complete ordinal selected network ID and connection generation. Known built-in `bridge`, `host` and `none` rows disable the entry points. The captured target never follows selection. The dialog displays its captured ID/generation, preparation identity/revision, acquisition phase, eligibility, all classified block reasons and inspected attachment observations. A bounded target preview includes its original length; deliberate target copy preserves the full exact ID.

| Evidence | Confirmation |
| --- | --- |
| Loading | Disabled while fresh Inspect is pending. |
| PrecheckEligible completed evidence | Enabled only for the exact current eligible preparation ID/revision. |
| Built-in or attached network | Disabled, with built-in/dependency block reasons and every returned attachment accessible. |
| Unavailable attachments | Explicit missing/null collection; never treated as observed empty. |
| Malformed or contradictory evidence | Classified reasons; disabled. |
| Invalidated, failed or consumed | Disabled; cannot renew authorization. Failure originals require deliberate reveal. |
| Revised or replaced preparation | Cannot silently become a new confirmation, including a formerly blocked preparation. Cancel and choose Delete again. |

The dialog explains that Inspect is a local observation, not cluster-wide attachment completeness, and cannot remove the check/delete race. An eligible empty attachment map is an observed collection, not a safety guarantee. No force option, dependency removal or uncertain-command replay is offered.

All returned attachment/container keys, names, endpoint IDs, MAC, IPv4 and IPv6 metadata remain accessible. Dictionary indexing runs off the UI thread; it retains one entry index for each currently relevant immutable inspection. Rows and bounded preview strings are projected on demand. Both preparation and retained-evidence lists use finite viewports with recycling `ItemsStackPanel`s. No eager text or control tree is constructed for the full collection. Selected-row deliberate copy runs off-thread, preserves complete identities/available metadata and distinguishes null from empty strings.

Cancel is the default button and receives initial focus. Confirmation captures one exact completed preparation identity/revision and consumes the presentation confirmation before reentrant Application notifications. Immediately before submission the view re-reads current resource, connection, pending operation and preparation snapshots. Application performs the final atomic admission/consumption. Duplicate invocation, stale dialog callbacks and a previous page lifetime cannot submit again.

Cancel, Escape, dialog closing, navigation, detail closure, selection changes, disappearance and connection invalidation fence confirmation. Cancellation/close fence before dialog close animation completes, cancel only presentation preparation, and asynchronously join its owned work. Non-cooperative preparation never blocks navigation or revives a closed dialog. A late completion cannot close a replacement preparation. The invoking control regains focus if usable, otherwise details Back or the selected network row does. Accepted mutation/reconciliation uses Application lifetime, without the canceled page token.

## Operation and conflict evidence

Ordinary status shows the original target/generation, pending/reconciling/completed phase, original command disposition and classified HTTP/failure, admission rejection, interruption, observed presence/absence, observation generation and invalidation. Command acknowledgement is separate from observed absence; acknowledged-but-present and uncertain-but-absent remain valid distinct combinations. Neither observation proves causation. Unresolved evidence explicitly prohibits automatic mutation replay.

Daemon attachment conflicts retain the original refusal and show the refreshed inspection's complete/unavailable/malformed/failed/invalidated state. Its collection is complete only for the returned Inspect observation, never a cluster-wide assertion. Historical preparation and refreshed conflict attachments are selectable through the retained evidence panel; every supplied endpoint remains accessible. Refresh never creates preparation or confirmation. Another attempt requires a new explicit precheck and confirmation.

Original daemon messages/error bodies, private failure descriptions and original target evidence are hidden by default. Deliberate Show/Hide prepares operation text off-thread and preserves original whitespace/null/empty values. Replacing an immutable snapshot, hiding evidence or detaching clears the reveal. Live immutable source identity, reveal/copy revisions and page lifetimes fence delayed reveal/copy callbacks, even before queued notifications drain. Notification delivery coalesces onto the existing UI dispatcher. No original metadata is logged, automatically exported or transmitted. Existing browser search, exact identity copy, Overview and actual raw JSON Inspect retain their independent behavior.

## Verification scope

Synthetic presentation checks compile the actual view without a graphical host and inject controlled Application services and a queued dispatcher. `--network-deletion-presentation` selects the focused groups. The smoke fixture supplies synthetic data only and has no Docker access. Its network deletion scenario selector covers observed empty, attachments, unavailable/failed/slow acquisition, 30,000 endpoints, event/generation/target invalidation, conflict, lost response, acknowledged-present and not-dispatched outcomes. **Run network deletion UI checks** exercises real Uno controls/dialogs/focus/recycling; **Run network UI checks** retains the browsing/Overview/Inspect checks and now expects Delete controls.

Real Windows Win32 keyboard, clipboard, accessibility and DPI behavior, non-elevated named-pipe ACLs, Docker Desktop/WSL2 deletion/event/dependency races, real driver/Swarm visibility and Engine restart behavior remain unverified on this macOS host. The synthetic fixture cannot establish those properties or workstation idle CPU/memory/snapshot-latency targets.
