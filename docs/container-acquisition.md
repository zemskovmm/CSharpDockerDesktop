# Read-only container acquisition

Application exposes `IContainerReader`. The negotiated Docker `IEngineConnection` implements this borrowed capability; DesktopSession obtains it from its retained connection. The owner of the connection remains responsible for replacement and disposal. The reader has no independent transport, disposal, Uno, or HTTP API. Presentation consumes `IContainerBrowser` for the Containers list, read-only Overview and raw Inspect. [Container event reconciliation](container-reconciliation.md) now coordinates automatic authoritative updates; other resource tables and lifecycle mutations remain pending.

`ListContainersAsync` sends `GET /v<negotiated>/containers/json?all=true`, including stopped containers. `InspectContainerAsync(identity)` sends `GET /v<negotiated>/containers/<escaped identity>/json`. IDs/names are encoded as one path segment; blank, excessive and dot-segment identities are rejected without I/O. Returned IDs are preserved in full rather than shortened. Read operations perform no mutations and no automatic retry.

Domain projections retain actual state/status strings, names, image references/IDs, ports, creation time, mounts and per-network relationships. Inspection also provides actual runtime flags, exit information, start/finish timestamps and health. Structured list health is consumed when supplied (introduced in API 1.52). Missing/null optional fields and collections remain unknown; empty collections remain empty. Future state strings and additive JSON fields are accepted. Incompatible known field types, invalid timestamps and invalid identities in responses are malformed data. Docker's zero start/finish time means never started/finished and projects to null. Projected timestamps have .NET's 100-nanosecond precision.

`ContainerInspection.RawJson` independently retains the complete actual UTF-8 response, including formatting, nanosecond timestamps, unknown properties, environment values and other sensitive content. It is not reserialized from projected fields or redacted. No response, identity, environment, mount path or raw inspect is automatically logged. Callers must keep deliberate display/copy/export separate from ordinary diagnostics and telemetry.

## Failure and lifetime contract

Results contain either a value or an `EngineResourceFailure`, with available HTTP status and the daemon's original JSON `message` or plain error text. Routine descriptions exclude that potentially sensitive message.

| Kind | Meaning |
| --- | --- |
| NotFound | HTTP 404: container disappeared or identity not found. |
| Conflict | HTTP 409 (or unexpected 304): state/dependency conflict. |
| InvalidRequest | Other 4xx: invalid/incompatible request, including API rejection. |
| AccessDenied | HTTP 401/403 or operating-system access denial, including wrapped denial. |
| DaemonFailure | Other non-success HTTP status, including 5xx. |
| MalformedData | Invalid JSON/consumed schema or successful body exceeding the byte limit. |
| TransportLoss | Interrupted transport, short-operation deadline, disposed connection or reopened pipe. |

Caller cancellation throws `OperationCanceledException`, even when HTTP wraps the cancellation; it is normal termination. A call begun after connection disposal throws `ObjectDisposedException`. Disposal cancels in-flight resource reads and they return TransportLoss unless caller cancellation takes precedence. Every request, response and response stream is released on success, failure and cancellation. Borrowed operations never dispose the connection's HTTP client. Connection disposal remains idempotent and solely owned by DesktopSession/the connection owner.

Requests and bounded response reading are asynchronous. JSON projection runs off the caller's thread. The existing `DockerConnectionOptions` governs short reads: initially five-second deadlines and one-MiB bodies, configurable up to sixteen MiB; this is a resource budget, not a latency promise. System.Text.Json also bounds JSON nesting to 64 levels. Oversized daemon errors keep their status/classification without retaining unbounded content. Pipe generation is checked before sending, after headers/body and after projection. A result from a reopened transport is rejected until a fresh connection negotiates current metadata; old readers do not silently retry against the replacement daemon.

## Application browsing state

DesktopSession implements `IContainerBrowser`. Consumers observe `ContainerSnapshot` and `ContainersChanged` without accessing a Docker client. Notifications can originate off the UI thread. `RefreshContainers()` requests a complete authoritative replacement. `SelectContainer(fullId)` loads inspection; null or an ID that disappeared from the current snapshot clears selection. `RefreshContainerInspection()` reloads the current selection, and `ClearContainerInspection()` cancels and clears its detail while retaining selection.

The snapshot distinguishes Unavailable, Loading, Ready and Failed. A Ready list with zero rows is a successful empty snapshot. Inspection also has NotRequested for cleared or unselected detail. Failures retain their original classified result and daemon message; actual raw Inspect JSON remains unchanged. These values are available for deliberate display, with no automatic logging or persistence. During a refresh the previous rows may remain visible with Loading/Failed state, but a successful list replaces them and removes duplicate full IDs. A selected ID missing from that list loses its selection and detail. Inspection NotFound additionally removes the corresponding row.

Every successful connection or recovery starts with an empty Loading snapshot and a new connection generation. At most one container read runs at a time. A bounded signal and latest-request flags coalesce refreshes and selections; superseded work is canceled, awaited and prevented from publishing. Refresh takes priority over pending detail work. Clearing inspection prevents a later refresh from reopening it. The configurable Application operation deadline bounds cooperative reads in addition to Infrastructure deadlines.

Connection replacement, loss and shutdown immediately invalidate rows and details, cancel associated reads, and await their cleanup before disposing the owned connection. Resource TransportLoss wakes the existing recovery workflow without waiting for the next readiness interval. It retains the classified resource diagnostic, stops subsequent reads on that connection and performs fresh negotiation before loading a new authoritative list. Ordinary daemon/resource errors remain resource failures on the retained connection. Reads themselves introduce no independent transport, mutations or snapshots on disk. DesktopSession also owns a negotiated event subscription and bounded authoritative reconciliation as described in [container reconciliation](container-reconciliation.md). Presentation consumes the browsing contract without owning the connection.

Controlled-reader tests cover initial/empty snapshots, replacement, full IDs/raw JSON, classified errors, NotFound and list disappearance, selection/refresh races, readers completing after cancellation, bounded concurrent work, fresh reconnect loading, resource-detected and readiness-detected loss, deadlines, and shutdown during list/inspection. The acquisition milestone passed **42/42 groups on macOS 26.7.1 with .NET SDK 10.0.402**. Current automatic event reconciliation evidence and the expanded suite are recorded in [container reconciliation](container-reconciliation.md); other resource screens and real Windows daemon evidence remain separate work.

## Container presentation

The Containers page receives `IContainerBrowser` from the shell-owned DesktopSession. It issues only Application browsing commands; Docker transport, protocol requests and retained connection ownership stay below Presentation. A finite-height Uno ListView with an explicit ItemsStackPanel owns its scrolling and recycles rows; it is not placed inside an outer scrolling container. Rows include all loaded states, name, short ID, image, state/status text, available health, ports and creation time. Full identity remains internal and is copied only through an explicit Copy full ID action. Missing values are unknown; explicitly empty collections are none.

Search filters loaded name, short/full identity, image/reference identity, state/status and available health. Projection and filtering run away from the UI thread; superseded searches are canceled. Rendering does not select resources through the Application contract or start reads. Selection is retained by full identity across filtering and successful refresh/reordering, and a deliberate Open Overview action starts inspection. Standard Tab, arrows, Enter and button activation reach search, list/detail refresh, opening and closing details; no global custom shortcut policy is introduced.

Overview shows the actual inspection projection: full identity/name/image, creation/start/finish times when available, runtime flags/state/exit information, health, ports, mounts and network relationships. Pending inspection and classified failures with available HTTP status have text descriptions and explicit refresh/retry. Inspect displays the complete retained raw response through a separate reusable presentation controller; switching tabs reuses the current Application inspection. No resource mutations or container-content diagnostic logging are added.

Initial loading, successful empty results, no search matches, pending refresh with previous rows, resource failure and unavailable connection have distinct messages. Connection recovery stays in the shell. Off-thread notifications are coalesced and dispatched to the UI, reading the latest snapshot there. Navigation detaches subscriptions and invalidates queued work. A disappeared identity or changed connection generation clears selection/details; closing Overview or leaving the page cancels inspection. Filtering does not reopen a closed detail.

### Raw Inspect viewer

Inspect uses a flat JSON index rather than a recursive visual tree. System.Text.Json parsing, projection, searching, expansion updates and copy preparation run on cancellable background work, serialized through one worker gate per viewer. A finite-height ListView with ItemsStackPanel recycles visible rows; long labels/value previews are limited to 240 characters for display, while search uses full decoded names/scalars and copying retains the entire exact JSON source slice. Unknown/additive fields, duplicate object names, null, empty objects/arrays, sensitive strings and number lexemes remain intact. No floating-point conversion or Overview reserialization occurs. Existing Infrastructure response-byte and nesting limits still apply.

Paths use `$` for the root, `[<JSON-encoded property name>,<zero-based occurrence>]` for an object property, and `[<zero-based index>]` for an array item. For example `$["Config",0]["Env",0][1]` identifies the second Env element; `$["duplicate",1]` identifies the second property named duplicate in the root object. Occurrences are always explicit, even for unique property names. This is a documented location notation, not JSON Pointer or a general JSONPath expression. Copy selected JSON value retains exact JSON syntax, including string quotes/escapes and sensitive content, and only runs after explicit button activation. Clipboard failures show a neutral status without logging exceptions or content.

Search includes descendants of collapsed nodes and displays matches with their ancestors. Search initially expands those ancestors; the user can then collapse/expand them. Clearing search restores normal expansion state. Tab reaches both tabs, search, copy, refresh and return controls. In the node list, arrows select, Right/Left expand/collapse, and Enter toggles the selected object/array. Buttons provide the same actions without requiring shortcuts. This defines local list interaction only.

The viewer is scoped to active details. Refresh clears obsolete content immediately; inspection loading/failure, identity changes, disappearance, connection generation changes, disconnect and page departure clear it and cancel work. A publication/copy guard checks the latest Application snapshot, so obsolete results cannot publish even before an invalidation notification drains. Returning to Overview reuses the current inspection and does not request Docker data. No browsing/search/expansion/copy action mutates the Engine or requests another inspection. Parser/display errors use fixed visible messages and do not log private exception text.
